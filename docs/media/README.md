# Media gallery

Screenshots and animated GIFs used by the README and docs. Everything under
`screens/` with a plain name is captured headless from the desktop simulator
with synthetic data (no account, device name, or token appears anywhere);
`hw-*.png` files are framebuffer dumps from a real Waveshare AMOLED 2.16
taken with `./screenshot.sh`.

## Regenerate

```bash
bash tools/make_gallery.sh                                   # sim screens + GIFs (builds the sim first)
node tools/convert_grid_animations.js --gif docs/media/animations   # GIFs only
```

`make_gallery.sh` needs PlatformIO, SDL2, ImageMagick (`magick` or `convert`)
and Node 18+. It plays `firmware/sim/gallery.jsonl` and takes one
`SIM_AUTOSHOT_MS` screenshot per screen at a fixed time; the GIF export is
byte-deterministic, the PNGs are stripped of date chunks. Screens that are
mid-animation when the shot fires (`claude-usage.png` status spinner, the two
scenes, `parade.png`) show the same content on every run but not always the
same frame, so their bytes may differ between runs. The hardware shots
are not regenerated by the script: re-capture them with
`./screenshot.sh docs/media/screens/hw-<name>.png [port]` when the UI changes.

## animations/

One animated GIF per text grid in `assets/animations/`, rendered at 6 px per
cell on black (palette index 0 draws as opaque black on the device splash,
exactly as here). Each frame keeps its own `hold`; the clip loops forever.
